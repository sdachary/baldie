description: Right-size a paid service to measured usage; name upgrade trigger + review date
---

Right-size this service per the baldie-scale skill of this repo. Start from measured/asked usage, not vibes: current
requests/rows/users/bandwidth, peaks, growth direction. Pick the smallest tier that fits measured need + 2-3x headroom, name
it, name the metric that forces the next step up, set a review date. Downgrade is a valid answer. Recompute per-seat vs flat
tiers at team size. If paid at all, never "just pick the pro tier". KEEP on security/compliance/backups/real-money paths.
